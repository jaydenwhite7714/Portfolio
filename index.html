01 What I do

Two jobs, one person.
Design and script, together.

Most teams hire a designer who can't code and a coder who can't design. I do both, so the interface you see in the mockup is the interface that ships — with the logic already wired behind it.

01

Game UI & UX

HUDs, shops, inventories, quest logs and menus that stay readable at any resolution.

  • Scale-based layouts for every device

  • Consistent spacing, radius and colour tokens

Combat & Abilities

Melee combos, projectiles, cooldowns and hit validation that can't be faked on the client.

  • Server-authoritative damage and hitboxes

04 Under the hood

The part players never see.
It still has to be clean.

Pretty frames are half the job. These are real patterns I use: server-side hit validation, UI that binds to state instead of guessing, and saves that don't lose data when Roblox has a bad day.

2local Players = game:GetService("Players")
3local Remotes = ReplicatedStorage.Remotes

5local COOLDOWN   = 0.65
6local MAX_REACH  = 9
7local lastSwing  = {}

9function CombatService.hit(player, target, abilityId)
10    -- server owns the truth: validate everything
11    if not target or not target.Parent then return end
12    if os.clock() - (lastSwing[player] or 0) < COOLDOWN then
13        return warn("rate-limited")
14    end
15
16    local dist = (player.Character.HumanoidRootPart.Position
17        - target.HumanoidRootPart.Position).Magnitude
18    if dist > MAX_REACH + 2 then return end -- too far
19
20    lastSwing[player] = os.clock()
21    local dmg = calculateDamage(player, abilityId, false)
22    applyDamage(target, dmg)
23    Remotes.HitFeedback:FireAllClients(target, dmg, abilityId)
24end

25Remotes.RequestHit.OnServerEvent:Connect(CombatService.hit)
26return CombatService

5function UIBinder.bind(state, render)
6    local conns = {}
7    for _, key in pairs(state) do
8        conns[key] = observe(state, key, function(value)
9            render(key, value)
10        end)
11    end
12    return function() table.clear(conns) end
13end

5local function withRetry(fn, attempts)
6    for i = 1, attempts do
7        local ok, result = pcall(fn)
8        if ok then return result end
9        task.wait(2 ^ i) -- 2s, 4s, 8s…
10    end
11    return nil, "retry-exhausted"
12end

14function SaveService.load(player)
15    local data = withRetry(function()
16        return store:GetAsync("u_" .. player.UserId)
17    end, 3)
18
19    data = data or Defaults.new()  -- new player
20    migrate(data)                    -- schema upgrades
21    Profiles[player] = data
22    pushToClient(player, data)
23end

Server stays in charge

Every hit, purchase and stat change is checked on the server. The client predicts for feel — never for truth.

UI binds to state

One data table drives every frame. Update the table, the interface follows — no scattered :SetText() calls.

Assume the network fails

Retries with backoff, autosave, session locks and migrations. Losing a player's progress is not an acceptable bug.

05 How I work

From messy idea to
playable in a week.

I keep the loop short and visible. You see progress every couple of days instead of one big reveal at the end that's three weeks off target.

  1. 01

    Brief

    We talk about the game, the players, and the feeling you want. I write a short scope doc with deliverables and a price.

    1–2 days
  2. 02

    Wireframe

    Layout in Figma at real Roblox resolution. You approve structure before a single Frame gets built.

    2 days
  3. 03

    Build

    Frames, UIGridLayouts, tweens and states — built in Studio with scale-based sizing from the start.

    3–5 days
  4. 04

    Wire

    Luau behind the interface: remote events, cooldowns, inventories, data. Tested on mobile and desktop.

    2–4 days
  5. 05

    Polish

    Sound, shake, hover states, edge cases. Two rounds of revisions included, then handoff with docs.

    1–2 days

06 About me

I got into scripting to make
a sword fight. I stayed for the UI.

I'm Jayden, a self-taught Roblox developer. It started with a combat system that was mostly RemoteEvents and hope — then I realised the reason it didn't feel good wasn't the code. It was that the player had no idea what was happening. No hit flash, no cooldown, no readable health bar.

So I learned interface design. Now I build both halves: the clean screen and the system behind it. I care about spacing, contrast and motion the same way I care about server authority and DataStore safety.

What I'm good at

  • Scalable UI that survives every screen size
  • Combat, abilities and cooldown systems
  • DataStore saves without data loss
  • UI/UX polish and game feel

Tools I live in

  • Roblox Studio · Luau
  • Figma for layout and specs
  • Blender for simple UI props
  • Git + Rojo for version control
